# Cleaning Bank Marketing Campaign Data for a PostgreSQL Database

![Piggy bank](piggy_bank.jpg)

## Overview

Personal loans are a lucrative revenue stream for banks. The typical interest rate of a two-year loan in the United Kingdom is [around 10%](https://www.experian.com/blogs/ask-experian/whats-a-good-interest-rate-for-a-personal-loan/). That might not sound like a lot, but in September 2022 alone UK consumers borrowed [around £1.5 billion](https://www.ukfinance.org.uk/system/files/2022-12/Household%20Finance%20Review%202022%20Q3-%20Final.pdf), which would mean approximately £300 million in interest generated by banks over two years.

This project is a case study in which a bank asks for help cleaning the data from a recent marketing campaign that aimed to get customers to take out a personal loan. The bank plans to run more campaigns, so the cleaned data must follow a **specific structure and set of data types**. That lets them set up a **PostgreSQL database** for this campaign and easily import data from future ones.

## Goal

Clean and reformat the raw `bank_marketing.csv` file, then split it into three CSV files (`client.csv`, `campaign.csv`, and `economics.csv`) with the exact column names, data types, and formats the bank specified.

## Output Files

### `client.csv`

| Column | Data type | Description | Cleaning applied |
|--------|-----------|-------------|------------------|
| `client_id` | integer | Client ID | N/A |
| `age` | integer | Client's age in years | N/A |
| `job` | object | Client's type of job | Changed `"."` to `"_"` |
| `marital` | object | Client's marital status | N/A |
| `education` | object | Client's level of education | Changed `"."` to `"_"` and `"unknown"` to `NaN` |
| `credit_default` | bool | Whether the client's credit is in default | `True` if `"yes"`, otherwise `False` |
| `mortgage` | bool | Whether the client has an existing mortgage (housing loan) | `True` if `"yes"`, otherwise `False` |

### `campaign.csv`

| Column | Data type | Description | Cleaning applied |
|--------|-----------|-------------|------------------|
| `client_id` | integer | Client ID | N/A |
| `number_contacts` | integer | Contact attempts to the client in the current campaign | N/A |
| `contact_duration` | integer | Last contact duration in seconds | N/A |
| `previous_campaign_contacts` | integer | Contact attempts to the client in the previous campaign | N/A |
| `previous_outcome` | bool | Outcome of the previous campaign | `True` if `"success"`, otherwise `False` |
| `campaign_outcome` | bool | Outcome of the current campaign | `True` if `"yes"`, otherwise `False` |
| `last_contact_date` | datetime | Last date the client was contacted | Built from `day`, `month`, and a new `year` column (2022), formatted as `YYYY-MM-DD` |

### `economics.csv`

| Column | Data type | Description | Cleaning applied |
|--------|-----------|-------------|------------------|
| `client_id` | integer | Client ID | N/A |
| `cons_price_idx` | float | Consumer price index (monthly indicator) | N/A |
| `euribor_three_months` | float | Euribor three-month rate (daily indicator) | N/A |

## Approach

1. **Load** `bank_marketing.csv` with pandas.
2. **Split** the data into three DataFrames (clients, campaign, economics) by selecting the required columns, using `.copy()` to avoid chained-assignment warnings.
3. **Clean text columns:** replace `"."` with `"_"` in `job` and `education`, and convert `"unknown"` education values to `NaN`.
4. **Convert to booleans:** map `credit_default`, `mortgage`, `previous_outcome`, and `campaign_outcome` to `True`/`False` using the bank's rules.
5. **Build the date column:** map month abbreviations to numbers, add a `year` of 2022, combine them with `day`, and format the result as `YYYY-MM-DD`.
6. **Export** the three DataFrames to `client.csv`, `campaign.csv`, and `economics.csv` without the index.

## Key Takeaways

- A single wide file was turned into **three tables that share `client_id`**, ready to be loaded into PostgreSQL as related tables.
- Data types were standardized (integers, floats, booleans, and dates), so future campaigns can be imported with the same structure.
- Missing education values are now real nulls (`NaN`) instead of the text `"unknown"`, so they won't be mistaken for a category.
